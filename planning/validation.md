# Spec validation — evidence audit

Completed by Codex at the user's explicit request to perform validation checks.
These are agent assessments for review, using the requirement text, implementation,
test assertions, fresh test execution and saved artifacts. They are not facilitator
approval. Each requirement in [spec.md](spec.md) has one mark below; absent or
partial submission evidence is marked **not met**.

Run from the repository root after activating the locked environment:

```bash
env -u API_KEY python3 -m unittest discover -s tests -v > planning/test-run.txt 2>&1
env -u API_KEY python3 tools/validate_submission.py
```

The fresh full run passed **89 tests**. The artifact audit checks the current
20-record generation against original source hashes, schema, quotes, issues and
expected routes, checks the saved 21-document accuracy report, request builder,
worksheet evidence links, and eight test-first/implementation commit pairs.
Open [validation-checks.json](validation-checks.json) for the recorded observations
and [test-run.txt](test-run.txt) for the full run.

The challenge's required mock validation scope applies: saved model replies and
injected HTTP transport exercise the application and comparison procedure. Marks
for extraction rules cover the prompt contract and those examples; they do not
claim live semantic accuracy, availability, throughput or universal instruction
attack detection. The note for each row records relevant limits. Live model runs
are optional and have not been performed. External R-78–R-80 remain not met
because their complete submission evidence has not been verified.
